# 完成公开问答的本地端到端验收

- Type: verification
- Status: ready
- Blocked by: 02-publication-indexing, 03-ask-runtime, 04-ask-page

## Outcome

在不部署生产的前提下，以真实 Supabase、Kimi/Pi、Next 运行时和浏览器证明公开资料问答可用、安全，并能以受保护的文件会话维持上下文。

## Scope

- 先执行数据库变更 dry-run，再在用户已授权的本地环境应用迁移并验证 PGroonga/权限/查询行为。
- 用可回滚的公开测试资料或现有公开投影，验证两条发布路径的索引新增、更新与撤回，不读取敏感源文件。
- 启动真实 Next 服务并使用浏览器验收：首页入口、三种范围、中文全文命中、README 章节引用、每日来源引用、流式输出、同一浏览器会话的连续追问与重载恢复、证据不足、Kimi 失败和 50/10 分钟限流。
- 执行受影响测试与项目要求的 `pnpm typecheck`、`pnpm lint`、`pnpm test`、`pnpm build`，并记录任何预存无关失败。
- 检查 API/浏览器存储/运行日志，证明不存在私有资料、凭据、原始指纹组成信息或跨访客会话正文泄露；检查 JSONL 文件位于 `var/`、被 Git 忽略且会按保留期清理。

## Acceptance

- 给出可复现的本地验证记录和浏览器证据；不以静态检查或模拟响应替代真实 Kimi/Pi 与 Supabase 路径。
- 所有受影响质量门通过，或明确保留并定位与本票据无关的既有失败。
- 没有生产部署、推送、公开数据扩张或提交行为被隐含执行。

## Notes

本票据是本地图的终点；向量检索、共享部署限流和跨实例/长期会话管理不属于验收范围。
