# 交付身份轨一致的公开问答页面

- Type: frontend feature
- Status: ready
- Blocked by: 03-ask-runtime

## Outcome

访客可以从首页进入 `/ask`，在与现有身份轨一致的内容流中选择资料范围、提问、观察流式回答，并检查每轮实际使用的来源。

## Scope

- 在首页增加“问一问”入口，并新增独立 `/ask` 路由；保留桌面优先的 identity rail 与连续内容流，不改造成工作台或卡片网格。
- 使用项目的 shadcn 基础消息组件组织用户消息、助手消息、输入区、自动滚动和加载/错误状态；保持现有黑白灰视觉约束。
- 提供“全部 / 每日关注 / 开源 README”范围选择；每轮助手回答附近显示服务端来源，README 显示仓库与章节定位，来源可跳转。
- 浏览器通过指纹生成当前会话标识，并将其随问答请求发送；页面可以保存可见消息状态，但不把全文对话写入 localStorage、sessionStorage、URL 参数或数据库。
- 消费既定 SSE 协议，处理首 token、取消/中断、网络错误、429、模型不可用与证据不足；支持最近上下文的连续追问。
- 满足键盘访问、屏幕阅读器状态通报、移动单列和 `prefers-reduced-motion`，并避免引入与既有首页冲突的显著动效。

## Acceptance

- 从首页到 `/ask` 的导航、资料范围切换、流式文本、来源链接、连续追问、429 和错误恢复均在真实浏览器可操作。
- 检查浏览器存储、URL 和网络响应不会暴露历史正文、原始指纹组成信息或服务端密钥；同一浏览器会话重载后可继续服务端文件会话，过期后则从新会话开始。
- 桌面布局仍保持左侧身份轨和右侧连续信息流；窄屏不横向溢出。

## Notes

不需要 Vercel AI SDK；API 的 SSE 契约和 shadcn 消息原语是唯一 UI 传输边界。
