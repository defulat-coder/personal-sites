# 公开资料问答地图

## 目的地

交付一个 `/ask` 公开问答功能：任意访客可在不登录的前提下，就本站已经发布的每日关注和公开仓库 README 提问。系统在 Supabase 中对公开资料执行中文全文检索，Pi Coding Agent 仅基于服务端召回的可回链资料流式作答。匿名对话上下文由本机受保护的 Pi JSONL 文件管理，不使用常驻内存会话表。

本次 Wayfinder 的终点是完整端到端交付；完成标准仅要求本地真实运行、真实浏览器和真实模型/数据库链路验证，不要求生产部署。

## 已锁定的产品与边界

- 入口：首页“问一问”进入独立 `/ask`，复用现有 identity rail，不挤入每日关注/开源切换器。
- 资料范围：默认全部，访客可切换每日关注或开源 README；每个答案展示实际命中的来源。
- 检索：Supabase 统一维护公开检索索引；首版只做 PGroonga 中文全文检索，不做向量、Embedding 或 RRF。
- 检索文档：每日关注按公开条目；README 按 Markdown 标题切分为可回链片段。
- 新鲜度：两条现有公开发布流程在发布资料时同步新增、更新和撤回检索文档。
- 生成：Kimi/Pi 只组织服务端下发来源；工具、技能、资源发现和私有资料访问均关闭；不展示思维过程。
- 对话：浏览器指纹生成当前会话标识，服务端使用其不可逆派生值定位专属 Pi JSONL 文件；会话支持最近少量轮次追问，不进入数据库、Git、浏览器存储或正文日志，并在保留期后自动清理。
- 传输与防护：SSE 流式回答；单 IP 每 10 分钟最多 50 次；本地内存实现保留替换共享限流器的接口。
- 观测：仅无正文的最小运行指标；问题与回答只存在于受保护的会话 JSONL 文件，不形成数据库档案或用户画像。

## 已知现状

- 公开资料已在 `public.x_curation_items` 与 `public.github_open_source_items`；当前没有全文索引、向量或问答运行时。
- 每日关注由 `modules/x-sync/publish-to-supabase.mjs` 发布；开源资料由 `modules/github-starred/publish-to-supabase.mjs` 发布。
- Kimi 现有配置只用于 Pi 的生成模型；Kimi 官方当前未提供可确认的 Embeddings API，因此向量检索不进入首版。
- Pi 0.84.1 的持久会话格式是 JSONL（每行一个 JSON 记录），`SessionManager.create/open()` 支持自定义会话目录与显式会话 ID。
- 当前工作区只有本次规划产生的 `CONTEXT.md` 与 `.scratch/public-ask/`；不触及敏感目录或本地凭据。

## 风险与后续分叉

- 必须在真实 Supabase 环境先验证 PGroonga 扩展可启用、中文查询行为和权限回收；否则不能仅以迁移文件宣称可用。
- 文件会话包含问题与回答正文，必须位于已忽略且受 Git 安全规则阻断的 `var/` 运行时目录；会话 ID 的原始指纹不得写入文件、日志或数据库，而是用仅服务端持有密钥的派生值定位，文件必须按保留期清理。
- 文件会话与本地内存限流不会跨进程或跨实例共享；这是本次“仅本地验证、不做部署”的明确边界。部署前须单独选择共享会话/限流策略。
- 语义向量、Embedding Provider 与 RRF 已明确排除首版；如需恢复，须以新地图重新评估成本、模型与索引重建。
