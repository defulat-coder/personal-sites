# 个人网站重设计 · 信息架构设计稿

> 状态：待确认 ｜ 日期：2026-08-07
> 背景：现有站点为"知识库 + 身份叙事"形态。经讨论，AI 时代知识囤积型内容失去展示价值，网站将整体重新设计为"活着的个人网站"。

---

## 1. 定位

**一句话**：一个每天会变化的个人站点——访客能看到你最近关注什么、在做什么、以及你怎么思考。

**内容主线**：输入 → 输出 → 视角

- **输入**：每日策展（X 平台关注内容的 AI 抓取 + 自动打标 + 个人点评）
- **输出**：项目案例（在做的智能体平台 SEAS 等，以决策叙事呈现）
- **视角**：关于我（职业叙事 + 工程观，克制、少量）

**不做**：知识库、教程、框架笔记等"知识囤积"内容。AI 时代的个人网站价值在于判断、决策与策展，而非信息搬运。

**读者**：技术管理者、同行工程师、潜在合作方。风格延续现有的克制编辑式调性。

---

## 2. 内容模型（三块）

### 2.1 每日策展（核心差异化）

每天从 X 书签/点赞中抓取感兴趣的内容，AI 自动摘要与打标，人工加点评后发布。

单条策展条目结构：

| 字段 | 说明 |
|---|---|
| title | 原内容标题/核心命题 |
| source | 原作者 + X 原文链接 |
| summary | AI 生成的一句话摘要 |
| take | **你的一句点评**（策展的灵魂，AI 草拟、人改） |
| tags | 自动标签，复用精简后的领域分类 |
| date | 策展日期 |
| status | draft / approved / published |

呈现形态：**按日期的信息流**为主视图，按标签可过滤。首页展示最近 3–5 条。

### 2.2 项目案例

每个项目一页深度案例，结构：**背景 → 我的角色 → 关键决策（为什么这么做，trade-off）→ 难点与坑 → 量化结果 → 技术栈**。

- 首批：SEAS 智能体平台（进行中的主项目，重点打造）
- 后续补充：喜马智能助手、HR 数据中台、地图中台等
- 企业内部项目以脱敏架构图 + 决策叙事呈现，不放截图和链接

### 2.3 关于我

- 一句话身份：11 年工程师，专注 Agent 工程
- 职业阶段时间线（沿用现有四阶段叙事）
- 工程观：现有首页 6 条 Agent 原则（上下文/工具/边界/证据/评测/恢复）予以保留——这是个人方法论，不是知识
- 联系方式：GitHub、邮箱

## 3. 首页结构

```
┌─────────────────────────────────────────┐
│ 头像 + 一句话身份 + GitHub/邮箱链接        │  ← 10 秒认知
├─────────────────────────────────────────┤
│ 每日策展（最近 3–5 条）                   │  ← 首屏主角，每天更新
│ 标题 · 标签 · 一句点评 · 日期              │
├─────────────────────────────────────────┤
│ 正在做的事：SEAS 项目卡片                 │  ← 状态 + 一句话价值 + 详情入口
├─────────────────────────────────────────┤
│ 项目案例（其余项目入口）                   │
├─────────────────────────────────────────┤
│ 关于我：职业时间线 + 工程观 6 原则         │
└─────────────────────────────────────────┘
```

原则：首屏给"新鲜感"，往下给"深度"。

## 5. X 策展管道设计

继承旧站已验证的治理模式：私有原始数据 → AI 整理 → 待审队列 → 人工批准 → 公开投影。

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ 抓取      │ → │ AI 整理   │ → │ 待审队列  │ → │ 人工批准  │ → │ 公开发布  │
│ 定时任务   │   │ 摘要+打标  │   │ draft    │   │ 加点评    │   │ 静态生成  │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

1. **抓取**：浏览器自动化走本机登录态，每天定时读取 X 书签/点赞列表（不依赖付费 X API）
2. **整理**：LLM 生成一句话摘要 + 自动打标（精简版领域分类：Agent 工程 / 架构 / 效能 / 行业观察……）
3. **待审**：写入 draft 队列，附 AI 草拟的点评建议
4. **批准**：人工确认/修改点评后标记 approved——这一步保证"策展是你的视角，不是搬运"
5. **发布**：生成静态页面，次日首页自然更新

执行方式：Kimi Work 定时任务（每天固定时间自动跑 1–2 步；3–4 步人工介入）。

### 技术选型（2026-08-07 调研结论）

不重写抓取层，采用现成开源方案组合：

- **日常增量：smaug**（github.com/alexknowshtml/smaug）
  - 基于 bird CLI + X 会话 cookie（`auth_token` + `ct0`），书签与点赞均可抓取，无需开发者账号
  - 内置 t.co 展开、外链正文/GitHub 仓库信息提取、Claude Code AI 分析打标、按日期输出 Markdown
  - 自定义分类可映射本站领域标签；纯 CLI，可挂定时任务无人值守
- **历史回填：twitter-web-exporter**（github.com/prinsss/twitter-web-exporter）
  - Tampermonkey 脚本，GraphQL 拦截，导出书签/点赞为 JSON，无官方 API 的 800 条上限
  - 用于一次性导出存量数据，作为首批策展内容
- 备选：TBD（Go daemon + SQLite 去重归档）、utkuvibing/twitter_scraper（Selenium）

## 7. 实施阶段

- **阶段 1 · 骨架**：新首页 + 三块路由 + 旧知识库下线（用现有内容占位）
