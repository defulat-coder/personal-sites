# 项目拥有记录，个人站按项目发布快照

能力、实验、决策、实践和里程碑都由稳定的项目身份拥有，不建立脱离项目的全局记录池。个人站通过通用来源适配器按项目增量采集私有证据，审核后将同一项目的已批准条目原子发布为一份公开快照；跨项目浏览只能从这些快照派生。采集检查点与公开修订分开推进，因此采集成功、解析失败、等待审核或发布失败都不会让未审核内容进入网站，也不会丢失下一次可恢复的同步位置。

## Considered Options

- 全局记录池能更快做统一时间线，但会丢失项目语境，并让同名能力、实验和决策难以归属。
- 每个项目直接向个人站写公开内容会把隐私审核和发布协议分散到多个仓库，难以保持一致。
- 项目级公开快照与当前“本地私有资料 → 审核 → SQLite 公开投影”边界一致，且单项目重跑、回滚和删除都能保持局部化。

## Consequences

- 新项目接入应只增加项目配置和已支持的来源适配器，不新增项目专用同步代码。
- 一条记录必须有唯一主项目；跨项目关系使用显式关联，不复制内容所有权。
- 公开站点永远读取最近一次成功公开修订，不能直接读取 Codex 历史、本地工作区或待审草稿。
